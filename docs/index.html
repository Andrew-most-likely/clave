What the hardening changes
  • The linux-hardened kernel with lockdown, IOMMU and init_on_free.
  • An nftables firewall that drops inbound traffic. OpenSnitch asks before apps connect out.
  • AppArmor with apparmor.d, auditd and a sysctl lockdown.
  • USBGuard, faillock, a stricter sudo, umask 027 and a noexec /tmp.
  • An AIDE baseline and a daily arch-audit check.

Good to know: USB devices you plug in later are blocked until you allow them. Three wrong passwords lock the account for 15 minutes. Skip all of it with --no-harden.

Recovery guide

How updates stay safe

Releases are signed, and clave-update installs only signed releases.

clave-doctor checks that Clave still works with what Arch installed. A pacman hook warns after an upgrade that this release was not tested with.

Install in one line.

On Arch Linux, as your normal user.

bash <(curl -fsSL https://raw.githubusercontent.com/Andrew-most-likely/clave/main/setup.sh)

Then log out and choose Hyprland. The installer asks before it changes anything.

Install by hand

Preview every change with --dry-run first.

git clone https://github.com/Andrew-most-likely/clave ~/.local/src/clave
cd ~/.local/src/clave
./install.sh --dry-run
./install.sh
Installer options
--yesNo questions. Hardening is included.
--no-hardenSkip the hardening.
--extrasAlso install the optional apps.
--personalUse fonts, a cursor and sounds you supply.
--user-onlyOnly your home folder. No sudo.
--dry-runShow what would happen. Change nothing.
Uninstall

Every file the installer replaced comes back. Packages stay installed.

~/.local/src/clave/uninstall.sh
~/.local/src/clave/uninstall.sh --system

The second line also removes the login screen, boot splash and hardening.

Questions.

Will it replace my Hyprland config?

It moves your old config aside to a dated backup and keeps your screens, wallpapers and Dock apps. uninstall.sh puts everything back.

Where do my own settings go?

~/.config/hypr/custom.lua for any Hyprland setting. The installer never replaces it.

Can I use my own logo?

Yes. Put an SVG at ~/.config/clave/branding/logo.svg.

Something broke. What now?

Run clave-doctor, then open an issue on GitHub with its output and ~/.cache/clave/install.log.
